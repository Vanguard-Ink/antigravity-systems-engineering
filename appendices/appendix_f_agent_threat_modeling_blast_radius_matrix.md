# Appendix F: Threat Modeling & Blast Radius Audit Checklist

This appendix formalizes the threat modeling taxonomy and operational risk evaluation framework for deploying autonomous coding agents in enterprise engineering environments.

---

## F.1 The Formal Agent Blast Radius Equation

The operational risk introduced by an autonomous agent process is mathematically modeled across four non-linear, interacting dimensions:

$$\text{Blast Radius} = \mathcal{C} \times \mathcal{A} \times \Omega \times \mathcal{I}$$

Where each parameter is normalized on a scalar scale from $0.0$ to $1.0$:

### 1. Capability ($\mathcal{C}$)
The breadth and expressiveness of executable tools available to the agent:
- $0.1$: Structured read-only AST inspection / regex search.
- $0.5$: Constrained file editing within targeted directory.
- $1.0$: Unrestricted arbitrary shell execution (`sh`, `bash`, `powershell`).

### 2. Access ($\mathcal{A}$)
The ambient authority, credentials, and network proximity inherited by the process:
- $0.1$: Ephemeral dummy files, mock environment variables, zero network access.
- $0.5$: Read-only access to repository and internal documentation proxy.
- $1.0$: Host ambient authority (`AWS_SECRET_ACCESS_KEY`, `~/.ssh/id_rsa`, `/var/run/docker.sock`, unrestricted internet egress).

### 3. Autonomy ($\Omega$)
The degree of unsupervised multi-step chain-of-thought and tool dispatch:
- $0.1$: Step-by-step human confirmation required for every mutation.
- $0.5$: Batch execution of predefined test plans with human review prior to commit.
- $1.0$: Continuous unattended daemon loop (cloning, building, mutating, git pushing, cloud deploying).

### 4. Irreversibility ($\mathcal{I}$)
The cost and technical feasibility of rolling back agent actions:
- $0.1$: Ephemeral Copy-on-Write sandbox (revert via unmount in <10ms).
- $0.5$: Git working directory (revert via `git reset --hard` before push).
- $1.0$: Irreversible external side effects (database drops, cloud infrastructure deletions, force-pushes to public repositories).

## F.2 STRIDE Taxonomy for Autonomous Agent Runtimes

| Threat Category | Classical Security Definition | Autonomous Agent Runtime Manifestation | Systems Mitigation |
| :--- | :--- | :--- | :--- |
| **Spoofing** | Impersonating an identity | Rogue subagent claiming to be host supervisor over socket. | Kernel-verified peer credentials (`SO_PEERCRED`), mutual HMAC handshakes. |
| **Tampering** | Modifying code or memory | Agent poisoned by indirect injection altering source files or build configs. | Ephemeral OverlayFS, read-only rootfs, pre-commit AST verification shims. |
| **Repudiation** | Denying performed actions | Agent claiming a destructive command was generated by compiler or user. | Non-repudiable JSON-RPC audit streaming over immutable pipe (`O_APPEND`). |
| **Information Disclosure** | Exposing private data | Ambient tokens leaked via `/proc/$PID/environ` or outbound HTTP curls. | Environment stripping (`env -i`), network namespace drop (`CLONE_NEWNET`). |
| **Denial of Service** | Exhausting resources | Infinite reasoning loops, fork-bombs, filling `/tmp` with massive artifacts. | cgroups v2 (`pids.max=64`, `memory.max=1G`), hard timeout watchdogs. |
| **Elevation of Privilege** | Escalating authorization | Bypassing allowlists via base64/IFS; escaping sandbox via kernel CVEs. | Seccomp-BPF filters, dropping all ambient capabilities (`PR_SET_NO_NEW_PRIVS`). |

## F.3 Enterprise Pre-Flight Security Audit Checklist

Before provisioning autonomous agent daemons in production or CI/CD pipelines, DevSecOps teams must verify the following invariants:

- [ ] **Ambient Environment Scrubbing**: Is the agent process initialized via `env -i` with sensitive cloud credentials stripped from memory?
- [ ] **Process Table Isolation**: Does the agent execute in a dedicated PID namespace (`CLONE_NEWPID`), hiding host PIDs and preventing signal cross-talk?
- [ ] **Network Egress Confinement**: Is outbound network access blocked by default (`CLONE_NEWNET` or nftables default-drop)?
- [ ] **File Descriptor Sanitation**: Are all inherited non-standard FDs closed (`close_range(3, ~0U, 0)`) before subshell execution?
- [ ] **Resource Ceiling Enforcement**: Are `memory.max` and `pids.max` enforced via cgroups v2?
- [ ] **Read-Only Root Filesystem**: Is the rootfs mounted read-only, restricting mutations strictly to an ephemeral OverlayFS layer?
- [ ] **AST Command Allowlisting**: Are commands validated against an AST grammar rather than naive regex blacklists?
- [ ] **Liveness Dead Man's Switch**: Is the daemon monitored by a supervisor watchdog (`WatchdogSec=30s`) that terminates reasoning freezes?
